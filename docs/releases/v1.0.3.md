# Fluval BLE v1.0.3

v1.0.3 fixes two visible bugs: a live-state bug in Auto and Professional
mode where the light entity could show a fixture as off with every channel
at zero while it was actually running its onboard schedule at full daytime
output, and a naming bug where a fixture with no advertised name was
labelled with its raw Bluetooth address instead of its model.

## Highlights

- **Auto/Pro light state now follows the onboard schedule.** Classic BLE
  status frames never carry live channel levels while a fixture runs Auto
  or Professional onboard - only Manual-mode frames do. The light entity
  previously took that absence at face value and rendered the fixture as
  off. It now derives what the fixture is actually doing right now from the
  last Auto/Pro schedule readback, using the same sunrise/sunset/sleep
  interpolation the native schedule preview command already used, so a
  fixture mid-ramp at midday now correctly shows on with the right
  brightness and colour.
- **Re-renders once a minute, no BLE traffic involved.** Because a schedule
  ramp changes level with no fixture notification at all, the light entity
  now re-renders from the last-known schedule every 60 seconds while in
  Auto or Professional mode. This never talks to the fixture; it only
  recomputes from data already in memory.
- **New `level_source` attribute.** Every light state update now reports
  where its displayed levels came from: `reported` (Manual mode, read
  directly off BLE), `schedule` (Auto/Pro, derived from the onboard
  schedule), or `unknown` (Auto/Pro before the schedule has been read back
  at least once). While `schedule`, a `scheduled_levels` attribute exposes
  the exact derived per-channel levels.
- **Fixtures are named after their model, never their MAC address.** A
  fixture whose advertisement carries no local name - or whose Bluetooth
  stack reports its own address as the name, which some stacks do - is now
  titled `Fluval <model>` (e.g. "Fluval Aquasky 900mm") on the discovery
  confirmation screen, the created config entry, and the device-registry
  entry, with entity_ids derived from that model name instead of the
  address. A fixture that does advertise a real local name keeps it
  unchanged. Configuring a second fixture of the same model disambiguates
  its default title with its last two MAC octets.

## Upgrade notes

No configuration changes are required. Fixtures running Auto or
Professional mode will show their real current state (including "on") as
soon as their next schedule readback lands after upgrading. For naming: an
existing fixture that was titled by its raw MAC address gets its
device-registry name (the device name shown in Settings > Devices &
Services, and the prefix on every entity's friendly name) corrected to the
model-based default the next time Home Assistant sets up the integration -
no action needed. The config entry's own title (the row in the integration
list) is stored at creation time and is unaffected; rename it manually if
you want it updated too. Already-assigned `entity_id`s are not renamed by
this change, so existing automations and dashboards keep working.

If a fixture behaves differently after upgrading, include its exact model,
Home Assistant version, downloadable Fluval BLE diagnostics, and relevant
logs in a GitHub issue.
