# Fluval BLE v1.5.5

v1.5.5 lets the integration free a light that a Bluetooth proxy is still holding
after the proxy itself has forgotten the connection.

## Fixed

- **A light stuck behind a "ghost link" now frees itself.** After a proxy glitch, the
  proxy's radio can keep the light's connection even though the proxy has forgotten it.
  The light thinks it is still connected, stops advertising, and nothing can reach it
  (on another light in the same house this lasted 22 hours). Now, if the light has not
  been heard by any proxy for 3 minutes since its link ended, the integration asks the
  proxy that last held it to drop its connections one at a time and stops as soon as the
  light is heard again. If the light is still silent (it may simply be unplugged), it
  tries again after 30 minutes, then 2 hours, then every 6 hours.

## Notes

This needs the proxy action `force_disconnect_handle` on the ESPHome proxy. A proxy
without it is left alone and the light keeps retrying as before. A light that is
heard but cannot be connected (for example all proxy slots busy) is never touched.
No settings, entities or actions were added; the Connection sensor gains two
attributes, `ghost_links_freed` and `last_ghost_try`, which also appear in diagnostics.
